## Context activation
Show the contextual developer panel only when a verifiable development event/work set is ACTIVE. Otherwise it remains hidden or presents "no verified active development". Display in the primary Whole-CLIC dashboard as a contextual section; do not generate a second unrelated dashboard/controller. On sub-facet/project dashboards inherit exactly the same grammar with local scope and authority.
Inputs: repository current, verified task registry IDs, native LifeCircle, daemon continuity, facet sub-LifeCircle, matching sub-Rehydration, source test reports and actual host acceptance. Never turn mere repo commits into task completion.

## Progress contract
active_total=COUNT_UNIQUE_SCOPED_TASK_IDS
done=COUNT_TASKS_WITH_VERIFIED_COMPLETION_EVIDENCE
progress=done/active_total only if denominator > 0 and all done states evidenced.
progress_unknown=HIDE_BAR_AND_SHOW_UNKNOWN
blocked, open, pending and disputed are separately counted; never conflate SOURCE_PASS with LIVE_COMPLETE.
When no audited task universe exists, use visible priority queue rather than percentage.

## Display
Native logo + native system header > compact development status strip > measured progress if valid > current step > completed verified steps > causal blockers and dependencies > relevant diagram > next authorized actor/action > return anchor > copyright.
Color: Neon Pink=current work; Neon Cyan=verified evidence; Neon Lila=hierarchy/rehydration; Neon Rosa=handoff. Warning/danger always labeled with words and icons. Responsive/mobile-readable. Do not invent creation or modification dates.
Stages: DISCOVER|ANALYZE|DESIGN|IMPLEMENT|TEST|HOST_ACCEPT|READBACK|CLOSE|BLOCKED|PAUSED. A pause may freeze one project (PET) without stopping unrelated active development.
Semantic reasoning: what changed, why it matters, evidence/contradiction, affected surfaces, who has authority, minimal next action, observed result.
No automatic daemon mutation or fabricated live sensor. SOURCE_NOT_RUNTIME until actual host readback.
